Scenario 1 — Healthcare

Hospital Patient Monitoring System

You are a biomedical engineer designing an AIoT monitoring system for a 20-patient hospital ward. Patient heart rate, SpO₂, and respiratory rate data must be processed with a maximum latency of 100 milliseconds per alert. Internet connectivity to the hospital's main server is sometimes interrupted for 5–10 minutes. Patient data is highly sensitive under healthcare privacy regulations. ⚕️ Note: This scenario is for educational systems design discussion only — not a specification for a real clinical system.

Which data processing architecture is most appropriate?

✅ Correct answer: Edge processing on a local hospital server or gateway.

Edge processing on a local hospital server ensures the 100 ms latency requirement is met regardless of internet connectivity. Latency to a remote cloud server over the internet would typically exceed 100 ms, and cloud-only processing would fail entirely during internet outages. Patient data remaining on-premises also satisfies privacy requirements more directly. Cloud can receive aggregated or summary data when connectivity is available.
Scenario 2 — Industrial

Manufacturing Equipment Bearing Fault Detection

A manufacturing plant wants to detect equipment bearing failures before they cause unplanned downtime. They have 3 months of vibration sensor data recorded during normal operation. However, actual bearing fault events are rare — they have only 5 labeled examples of fault-condition data from past incidents.

Which machine learning approach is most appropriate given this data situation?

✅ Correct answer: Anomaly detection / Isolation Forest.

With only 5 labeled fault examples, a supervised classifier will be severely imbalanced and unreliable — it cannot generalise from 5 examples. Anomaly detection algorithms like Isolation Forest learn what 'normal' looks like from the abundant normal data, and flag readings that deviate significantly. This is the standard approach when fault data is scarce (which is typical in real industrial settings). Simple threshold rules (option D) are valid as a baseline but miss subtle multi-dimensional patterns that anomaly detection captures. K-Means (option C) is unsupervised clustering and not well-suited to this binary-anomaly detection task.
Scenario 3 — Agriculture

Smart Agriculture Soil Monitoring Network

A smart agriculture cooperative wants to deploy soil moisture sensors across 50 farm plots distributed across a 15-kilometre radius from the nearest town. Each sensor should transmit soil moisture readings every 5 minutes. Farms have no reliable mains power — sensors must run on small solar + battery power for months. Cost is a significant constraint.

Which wireless connectivity technology is most appropriate?

✅ Correct answer: LoRaWAN (Long Range Wide Area Network).

LoRaWAN is specifically designed for this exact scenario: long range (up to 15 km in rural open terrain with line-of-sight), very low power consumption (nodes can run on battery/solar for months or years), low data rate (perfect for small sensor readings every few minutes), and low infrastructure cost. Wi-Fi range is typically 50–100 m. Bluetooth range is typically 10–30 m. 5G provides high speeds but has high power consumption, high device cost, and requires cellular coverage which may be absent in remote agricultural areas.

⚡ Section B — Rapid-Fire True / False 0 / 5 correct

Statement 1: MQTT requires a persistent internet connection to function.

MQTT works on local networks without internet access. A broker can run on a local Raspberry Pi.

Statement 2: A rule-based threshold system always requires less data to implement than a trained ML model.

Rule-based systems rely on expert-defined thresholds rather than training data. They can be deployed immediately but may be less adaptive than ML.

Statement 3: Edge computing and cloud computing are mutually exclusive — you must choose one.

Most AIoT systems use both: edge for low-latency local decisions, cloud for analytics, storage, and advanced processing.

Statement 4: A DHT22 sensor can directly diagnose medical conditions without clinical validation.

Sensors and systems must be clinically validated and regulatory approved for any medical use. Consumer sensors are not medical devices.

Statement 5: LoRaWAN is designed for high-bandwidth, low-latency applications like video streaming.

LoRaWAN is designed for low-bandwidth, low-power, long-range applications with low data rates. It is not suitable for video streaming.
